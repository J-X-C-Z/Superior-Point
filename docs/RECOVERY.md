# 保存失败与文件交接

## 先保护内存中的改动

保存失败时，状态不会显示“已保存”。最新内容仍在当前会话内，关闭页面可能丢失这些改动。可先“导出备份 JSON”；它保存完整文档数据，不依赖基础渲染器是否支持所有样式。JSON 是备份入口，不会执行里面的脚本字符串。

暂时性存储错误可使用“重试保存”。如果另一标签页已接管或原项目出现修订冲突，不应把旧快照强行写回。

## 恢复为独立项目

使用恢复副本操作，将当前内存内容另存为新的项目。恢复操作不覆盖原项目或其他标签页的内容；恢复开始前已经发出的保存可能正常完成。恢复期间停止接受新编辑，等待已有写入结束；只有新副本持久创建成功后，才清理旧会话并尝试打开副本。

创建失败时，旧会话、待保存内容和 JSON 备份入口继续保留。若浏览器存储配额已满，副本也可能无法创建，此时请先导出 JSON。不要清理站点数据来“修复”保存失败，因为那会同时清除已有本地项目。

新副本采用新的项目 ID 和起始修订号，保留页面、元素 ID、资源、扩展字段及原始文档内容，并记录恢复来源。它不是把旧项目回滚，也不是合并两个标签页的改动。撤销历史属于原来的会话，不随副本转移。

## 重新导入和 MCP 交接

- JSON 备份：在工作台选择“打开本地文件”，导入为独立项目，不覆盖同名或同 ID 的现有项目。
- 浏览器到 MCP：导出可编辑 HTML，将文件放入显式授权的 MCP 项目目录，再调用 `sp_open_project` 的 `filename` 入口。已存在的项目 ID 会报冲突，不会覆盖。
- MCP 到浏览器：使用 `sp_save_export` 导出 HTML，再从工作台导入；浏览器创建新的独立项目。
- `sp_open_project` 的文件入口目前只接受 HTML；JSON 备份不能直接作为它的 `filename`。

交接是用户明确执行的文件操作，没有后台同步或自动读取其他目录。高级图片效果和未知元素仍可保存在数据中，基础 HTML 预览可能无法完整绘制；导出时会报告已知缺口。

## 验证范围

自动化覆盖使用 JSDOM 和 fake-indexeddb 验证故障与竞态路径。真实浏览器跨重启、真实多标签和 `file://` 离线运行仍待验收；见 `VALIDATION.md`。
