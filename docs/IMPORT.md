# 安全导入与明确文件交接

## 支持的文件

工作台“打开本地文件”支持本框架导出的可编辑 HTML，以及完整文档 JSON 备份。二者都会创建独立项目，不覆盖现有项目 ID。这里的“可编辑”指完整结构化文档仍在文件中；当前已接入用户正式交接的 v0.39 编辑器，验收范围详见 VALIDATION.md。

现有 schemaVersion 0 原型可以按 Core 中的显式规则迁移到 schemaVersion 1。更高 canonical 版本和普通网页仍拒绝。开启候选编辑器时可显式识别原编辑器 version:1 JSON，以及包含 superior-point-project 惰性数据块的演示 HTML；编辑器程序 HTML 本身仍不能当成项目导入。遇到不支持的格式请保留原文件，不要手动更改版本号强行导入。

## 导入的提交边界

文件先经过大小、格式与文档结构检查。导入串行进入导航队列；如当前项目还有改动，必须先成功保存，才会创建导入项目。当前保存失败时仍留在原项目，可重试保存或先恢复为独立项目，不会产生隐藏导入副本。

创建失败会保留原会话。新项目完成持久创建后，即使旧锁清理或新项目打开失败，已提交内容仍在项目库中，并给出可以回到工作台的提示。不要仅因为“打开失败”就反复导入同一文件。

同名文件导入不会替换同名项目。项目名称用于展示，唯一身份仍是项目 ID。页面、元素、资源及扩展字段保持原始内容；导入身份、修订号和时间按独立项目重新建立。

## 安全和错误提示

HTML 仅提取惰性的结构化文档，不执行外围脚本；JSON 只解析数据。错误和来源名称用文本显示。原有资源检查和基础渲染器继续生效，导入成功不意味着高级样式已经完整呈现。

超大文件、无效 JSON、缺少文档数据、文档结构错误和不支持的版本会明确报错。失败后可再次选择同一文件，不必刷新页面。

## MCP 文件交接

MCP 项目与浏览器库仍是分开的存储位置。使用真实 stdio 客户端的 `sp_save_export` 在已授权目录生成 HTML，再从工作台选择这个文件。工作台导入会生成新 ID，保留内容，之后可以继续通过 Core/适配接口修改并导出。

反向交接用工作台导出的 HTML 和 MCP `sp_open_project({filename})`。MCP 的文件入口只接受 HTML，不接受 JSON 备份；同 ID 冲突会拒绝，而不会覆盖已有项目。没有网络账号、自动同步或后台目录访问。

## 验证边界

自动化覆盖真实 MCP SDK 子进程、文件导出以及 JSDOM/fake-indexeddb 中的首页导入和再次编辑。不是已通过真实浏览器点击、布局或跨重启验收，详见 `VALIDATION.md`。
# 观众分享文件

“分享观众 HTML”是独立放映文件，移除了备注、批注、历史、隐藏页及可编辑项目 JSON。它不能导入为项目；需要继续编辑或 MCP 文件交接时，请使用“备份可编辑 HTML”或 JSON 备份。
